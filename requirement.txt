==================================================
1. PROJECT OBJECTIVE
==================================================

Build a web-based cybersecurity training platform where users can learn how to identify, investigate, and respond to simulated cloud cybersecurity incidents.

The platform should provide:

- User authentication and authorization
- Student/user dashboard
- Cybersecurity training scenarios
- Cloud incident simulations
- Interactive incident investigation
- Logs and security events
- User actions during simulations
- AI assistant
- AI-generated hints and explanations
- AI-assisted analysis of user actions
- Simulation scoring
- Progress tracking
- Training history
- Admin panel
- Scenario management
- User management
- Statistics and analytics

The system should simulate cloud cybersecurity incidents safely. Do NOT build functionality intended to attack real external systems.

The simulation environment should be isolated and controlled.

6. CYBER INCIDENT SIMULATIONS
==================================================

Create several safe educational scenarios.

Initial scenarios can include:

1. Brute-force attack against a cloud VM
2. Compromised user credentials
3. Excessive IAM permissions / privilege escalation
4. Publicly exposed cloud storage
5. Suspicious login
6. Data exfiltration indicators
7. Cloud security misconfiguration

For the first implementation, fully implement 2-3 scenarios rather than creating many incomplete scenarios.

Each scenario should contain:

- Title
- Description
- Difficulty
- Learning objectives
- Initial infrastructure state
- Incident timeline
- Logs/events
- Alerts
- Evidence
- Expected investigation steps
- Expected response actions
- Optional hints
- Scoring rules
- Explanation of the incident
- Recommended solution

Simulation examples:

Scenario:
Compromised Cloud VM

Evidence:
- Multiple failed SSH login attempts
- Successful login from suspicious IP
- New privileged user created
- Suspicious process started
- Unexpected outbound traffic

Expected student actions:
- Identify suspicious authentication activity
- Investigate relevant logs
- Identify compromised resource
- Isolate VM
- Disable compromised credentials
- Recommend credential rotation
- Review access permissions

The simulation must be deterministic enough to test, but designed so AI can later add variation.

7. SIMULATION ENGINE
==================================================

Design a reusable simulation engine.

Possible state lifecycle:

CREATED
→ RUNNING
→ INVESTIGATING
→ RESPONDING
→ COMPLETED

Store important actions performed by the student.

Example:

SimulationAction:
- timestamp
- simulationId
- userId
- actionType
- targetResource
- metadata
- result

The scoring engine should evaluate the user's actions against scenario expectations.

Example scoring:

Correct incident identification: +20
Correct compromised resource: +15
Correct log investigation: +10
Correct containment action: +20
Credential rotation: +10
Permission review: +10
Incorrect destructive action: -10
AI hint usage: optional small penalty

Keep scoring configurable.

==================================================
8. AI ASSISTANT
==================================================

AI is an important part of the graduation project.

Do not make AI only a chatbot placed on the page.

It should have a meaningful role.

AI capabilities should include:

A. CONTEXTUAL ASSISTANT

AI receives:
- current scenario
- incident description
- visible evidence
- actions already performed
- current simulation state

It can provide educational hints without immediately revealing the complete solution.

B. POST-SIMULATION ANALYSIS

After completion, AI should analyze:

- correct actions
- mistakes
- missed evidence
- action order
- unnecessary actions

Then generate feedback.

Example:

Score: 82/100

Strengths:
- Correctly identified the compromised VM
- Investigated authentication logs
- Isolated the affected resource

Improvements:
- Credentials should have been rotated earlier
- IAM permissions were not reviewed

C. SCENARIO GENERATION / VARIATION

If practical, allow AI to generate variations of existing scenario templates.

However, AI-generated content must be validated before it affects application state.

D. LEARNING RECOMMENDATIONS

Based on previous simulations, AI may recommend topics such as:

- IAM security
- Network security
- Incident response
- Authentication security
- Cloud logging

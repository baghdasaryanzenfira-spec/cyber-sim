# 07 — Հաճախորդային մասի (frontend) իրականացում

> Ծավալը՝ **ադմինիստրատորի սցենարների հեղինակման հարթակ** (տե՛ս [17-admin-authoring-platform.md](17-admin-authoring-platform.md))։
> SPA-ն ունի ուղիղ մեկ լսարան՝ ադմինիստրատորը, որը գեներացնում, խմբագրում, վերլուծում, հրապարակում և
> տարբերակավորում է սցենարները։ Ուսանողական էջեր չկան։

## 1. Կառուցվածքը

```
frontend/
├── index.html
├── vite.config.ts          dev proxy /api → http://localhost:8080
├── Dockerfile              build Node-ով, մատուցում nginx-ով (+ /api reverse proxy)
└── src/
    ├── main.tsx            React root, ThemeProvider, Router, i18n և տառատեսակների ներմուծումներ
    ├── App.tsx             երթուղիների սահմանումներ
    ├── theme.ts            Մուգ «SOC» թեմա
    ├── api/                client.ts (axios + JWT interceptor), endpoints.ts (տիպիզացված API ֆունկցիաներ), types.ts
    ├── auth/               AuthContext, guards.tsx (RequireAuth, RequireAdmin)
    ├── hooks/              useLoad (load / error / reload վիճակ)
    ├── i18n/               index.ts (i18next կարգավորում), en.ts, hy.ts (UI-ի թարգմանություններ)
    ├── components/         Layout, Chips, StatTile, Feedback, LanguageSwitcher, TranslateButton
    └── pages/
        ├── AuthPages.tsx   ադմինի մուտք (առանց գրանցման)
        └── admin/          AdminDashboardPage, GeneratorPage, AdminScenarioPages (ցանկ + խմբագրիչ),
                            AuthoringPanels (վերանայում/տարբերակներ), GraphPanel, RowEditor, scenarioMeta
```

## 2. Հիմնական որոշումներ

| Որոշում | Ինչու | Այլընտրանք |
|----------|-----|-------------|
| Պարզ React վիճակ + Context՝ նույնականացման համար | Քիչ գլոբալ վիճակներ (միայն օգտատերը/տոկենը). Redux-ի կարիք չկա | Redux Toolkit, Zustand |
| Տիպավորված API շերտ (`api/*.ts`), որը կրկնում է backend-ի DTO-ները | Պայմանագրի անհամապատասխանությունների հայտնաբերում կոմպիլյացիայի ժամանակ | Չտիպավորված axios կանչեր կոմպոնենտներում |
| MUI՝ հատուկ մուգ թեմայով | Պրոֆեսիոնալ տեսք էկրանապատկերների համար՝ նվազագույն հատուկ CSS-ով | Tailwind |
| JWT-ը պահվում է `localStorage`-ում | Պարզ է bearer տոկեններով SPA-ի համար. ռիսկը մեղմվում է կարճ ժամկետով և React-ի խիստ էսկեյփինգով (առանց `dangerouslySetInnerHTML`) | HttpOnly cookie (պահանջում է CSRF պաշտպանություն և same-site կարգավորում) — փաստաթղթավորված է որպես ապագա բարելավում |
| `react-i18next`՝ անգլերեն/հայերեն ինտերֆեյսի համար | Փաստացի ստանդարտ, առանց provider-ի ավելորդ կոդի (`useTranslation` hook), ինտերպոլացիա և լեզվի փոփոխություն առանց վերաբեռնման | Ձեռքով գրված context (առանց ինտերպոլացիայի). URL-ով նախածանցված երթուղիներ (`/hy/...`) — ավելորդ է մեկ օպերատորի գործիքի համար |

### ADR-11 — Ինտերֆեյսի թարգմանությունը տիպիզացված ռեսուրսների փաթեթներով

- **Ինչ.** Ինտերֆեյսի բոլոր տեքստերը գտնվում են `src/i18n/en.ts` և `src/i18n/hy.ts` ֆայլերում՝ խմբավորված ըստ
  ոլորտների (`common`, `nav`, `auth`, `dashboard`, `generator`, `aiSource`, `list`, `editor`, `review`,
  `graph`, `versions`, `translate`, `enums`)։ Կոմպոնենտները կարդում են դրանք `useTranslation()`-ով. `hy.ts`-ը
  հայտարարված է որպես `typeof en`, ուստի TypeScript կոմպիլյատորը մերժում է բացակայող կամ սխալ գրված բանալին —
  երկու փաթեթները չեն կարող շեղվել իրարից։
- **Ծավալը.** Միայն ինտերֆեյսի տարրերը։ Սցենարի *բովանդակությունը* (վերնագրեր, մատյանների հաղորդագրություններ,
  գործողությունների անվանումներ) ցուցադրվում է ճիշտ այնպես, ինչպես հեղինակվել է. փոխարենը այն թարգմանվում է ըստ
  պահանջի՝ ամեն տեքստի կողքի *Թարգմանել* կոճակով, որը նկարագրված է ADR-12-ում (09-ai-integration.md)։
- **Փոխարկում.** `LanguageSwitcher`-ը (EN / ՀԱՅ) գտնվում է վերին վահանակում և մուտքի քարտում։ Ընտրությունը
  պահվում է `localStorage`-ում՝ `cybersim.lang` բանալիով, և կիրառվում `<html lang>`-ի վրա. կարդալն ու գրելը
  փաթաթված են `try/catch`-ով, ուստի գաղտնի դիտարկման ռեժիմը վերադառնում է լռելյայն լեզվին (անգլերեն)՝ առանց սխալի։
- **Enum-ների պիտակները.** backend-ի enum-ները (`ScenarioStatus`, `Difficulty`, `Category`, `Severity`,
  `ActionOutcome`, `ScenarioType`, խնդիրների կարևորություններ, թեստային ուղիներ, որակի գնահատականներ)
  թարգմանվում են `enums` տարածությունում և ցուցադրվում chip կոմպոնենտներով, ուստի ինտերֆեյսը կարդացվում է
  ընտրված լեզվով, իսկ API պայմանագիրը մնում է անփոփոխ։
- **Տառատեսակներ.** Inter-ը հայկական գլիֆներ չունի, ուստի `@fontsource/noto-sans-armenian`-ը տեղադրված է նրա
  կողքին և դրված տառատեսակների շղթայում երկրորդ տեղում. դիտարկիչն ընտրում է այն ըստ յուրաքանչյուր գլիֆի՝
  լատինատառ տեքստը թողնելով Inter-ի վրա։ Երկուսն էլ ներառված են build-ում, ուստի հարթակը արտաքին տառատեսակների
  CDN-ի կարիք չունի։

## 3. Երթուղիներ և էջեր

Երթուղավորում՝ `createBrowserRouter`՝ ներդրված layout երթուղիներով. `RequireAuth` և `RequireAdmin` պահակներ
(միայն UX — թույլտվությունները պարտադրում է backend-ը)։ `/`-ը վերահղվում է `/admin`. անհայտ ուղիները՝ `/`։

| Երթուղի | Էջ | Նշանակություն |
|-------|------|---------|
| `/login` | `AuthPages.tsx` | Ադմինի մուտք EN/ՀԱՅ փոխարկիչով. գրանցման հղում չկա — հաշիվները ստեղծում է օպերատորը |
| `/admin` | `AdminDashboardPage` | Կարգավիճակների վիճակագրական սալիկներ (ընդամենը / սևագրեր / հրապարակված / արխիվացված), հեղինակման 8-քայլ հոսքը՝ որպես ուղեցուցային ցանկ, 5 վերջին թարմացված սցենարները |
| `/admin/generate` | `GeneratorPage` | Սցենարի գեներատորի ձև՝ տեսակ, վերնագիր, բարդություն, հիմնական ակտիվ, հարձակվողի IP, տարածաշրջան, ազատ նկարագրություն (brief), `useAi` անջատիչ. հաճախորդի կողմի ստուգումները կրկնում են backend-ի `@Pattern` կանոնները, սերվերի դաշտային սխալները հայտնվում են համապատասխան դաշտերի վրա |
| `/admin/scenarios` | `AdminScenariosPage` | Բոլոր սցենարները՝ կարգավիճակի նշանով, revision-ով, հրապարակված տարբերակով. արխիվացում/վերականգնում, ջնջում (միայն երբեք չհրապարակվածների), AI վարիացիա |
| `/admin/scenarios/new`, `/admin/scenarios/:id` | `ScenarioEditorPage` | Ամբողջական խմբագրիչը (հաջորդ բաժինը) |

## 4. Սցենարի խմբագրիչը

Մեկ էջ՝ ինը ներդիրով. վերջին երեքը գոյություն ունեն միայն պահպանված սցենարների համար։

| Ներդիր | Բովանդակություն |
|-----|---------|
| Ընդհանուր | մետատվյալներ, տուգանքներ, նպատակներ, միջադեպի բացատրություն, խորհուրդ տրվող լուծում |
| Ենթակառուցվածք | սիմուլյացված ամպային ռեսուրսներ (`RowEditor` երկխոսություն յուրաքանչյուր տողի համար) |
| Մատյաններ, ահազանգեր և ապացույցներ | միջադեպի ժամանակագրությունը. ապացույցի նշանները և `revealedByActionKey`-ը յուրաքանչյուր իրադարձության համար |
| Գործողություններ և գնահատում | գործողությունների կատալոգը՝ փուլերով, արդյունքներով, միավորներով և նախապայմաններով |
| Հուշումներ | ստատիկ հուշումներ՝ մեկ տողում մեկը |
| JSON | ամբողջ սահմանումը որպես խմբագրելի JSON (կիրառելը փոխարինում է ձևի վիճակը) |
| Վերանայում | վավերացման հաշվետվություն, թեստային ուղիներ՝ ստուգում առ ստուգում արդյունքներով և բացվող քայլերի աղյուսակներով, որակի միավորի բաշխում, հրապարակման վահանակ |
| Գրաֆ | կախվածությունների գրաֆը (`GraphPanel`) |
| Տարբերակներ | հրապարակված տարբերակները՝ գնահատականով և փոփոխության նշումով. սառեցված սահմանման դիտում, վերականգնում սևագրի մեջ |

Իրականացման նշումներ.

- **Կենդանի գնահատում չպահպանված բովանդակության վրա.** Վերանայման ներդիրը գնահատում է *խմբագրիչի ընթացիկ
  վիճակը* `POST /api/admin/scenarios/evaluate`-ի միջոցով, ուստի արձագանքը թարմանում է խմբագրելիս — բայց
  **հրապարակման կոճակն օգտագործում է պահված սևագիրը** և անջատված է, քանի դեռ խմբագրիչում չպահպանված
  փոփոխություններ կան (`review.saveFirst`)՝ համապատասխանելով սերվերային պայմաններին։
- **Գրաֆի դասավորություն.** `GraphPanel`-ը հանգույցները դասավորում է ինքը (առանց գրաֆային գրադարանի)՝ start →
  գործողություններն ըստ նախապայմանի խորության → յուրաքանչյուր իրադարձություն՝ այն բացահայտող գործողությունից
  անմիջապես հետո → ռեսուրսները վերջում, գծված որպես սովորական SVG։ Ռելաքսացիայի ցիկլը սահմանափակված է
  գործողությունների քանակով, ուստի նախապայմանների ցիկլը (որը վավերացումը միևնույնն է զեկուցում) չի կարող
  կախեցնել դասավորությունը։ Վահանակը վերաբեռնվում է ըստ պահպանված revision-ի և ցուցադրում նշում, երբ
  չպահպանված փոփոխությունները նկարում չեն։
- **`RowEditor`.** մեկ ընդհանրական երկխոսություն՝ ղեկավարվող դաշտերի սպեցիֆիկացիաներով, մշակում է ռեսուրսները,
  իրադարձությունները և գործողությունները. ընտրության տարբերակները (ռեսուրսների բանալիներ, հետաքննական
  գործողություններ) ստացվում են ընթացիկ սահմանումից, ինչը կանխում է հղումային սխալների մեծ մասը դեռ մինչև
  backend-ի վավերացնողի աշխատելը։
- **Բովանդակության թարգմանություն.** `TranslateButton`-ը (փոքր ներտողային հղում, որի հիմքում
  `POST /api/ai/translate`-ն է) գտնվում է խմբագրիչի իրադարձությունների մատյանի հաղորդագրությունների կողքին,
  որպեսզի հեղինակը ցանկության դեպքում հայերեն կարդա անգլերեն տելեմետրիան. ոչինչ չի քեշավորվում կամ պահպանվում
  (ADR-12)։
- **Տվյալների բեռնում.** փոքր `useLoad` hook-ը (բեռնում, սխալ, վերաբեռնում, տեղային թարմացում)՝ տվյալներ
  ստանալու գրադարանի փոխարեն — հավելվածն ունի քիչ ու պարզ հարցումներ։

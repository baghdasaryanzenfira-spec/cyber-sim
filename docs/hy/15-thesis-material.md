# 15 — Ավարտական աշխատանքի նյութեր

Նյութերը դասակարգված են ըստ ավարտական աշխատանքի երեք բաժինների։ Յուրաքանչյուր կետ հղում է անում մանրամասն
փաստաթղթին, իսկ նկարների ցանկը ներկայացված է [thesis-figures.md](thesis-figures.md) փաստաթղթում։

## Բաժին 1 — Հարթակում օգտագործվող տեխնոլոգիաների և մեթոդների հետազոտություն

**1.1 Առարկայական տիրույթ**
- Ամպային համատեղ պատասխանատվության մոդելը (shared-responsibility model). ամպային միջադեպերի մեծ մասը
  պայմանավորված է հաճախորդի կողմի սխալ կարգավորումներով (misconfiguration) և նույնականացման տվյալների
  վտանգվածությամբ (03 §1.1)։
- Միջադեպերի արձագանքման կենսացիկլը (NIST SP 800-61) և դրա համապատասխանեցումը սիմուլյացիայի վիճակներին
  (03 §1.2, Նկ. 1)։
- Հետաքննություններում օգտագործվող ամպային լոգերի աղբյուրները՝ նույնականացման լոգեր (auth logs), աուդիտի
  հետք (audit trail), մուտքի լոգեր (sign-in logs), ցանցային հոսքերի լոգեր (flow logs), պահոցների հասանելիության
  լոգեր, սպառնալիքների հայտնաբերման ահազանգեր (03 §1.3)։

**1.2 Ուսուցման մեթոդներ**
- Կիբեռպոլիգոններ (cyber ranges)՝ նախապես պատրաստված տելեմետրիայով սիմուլյացիայի և տեսական դասընթացների
  համեմատությամբ. ընտրված մեթոդը որոշումների կայացման աշխատանքային հոսքը ուսուցանում է անվտանգ, էժան և
  դետերմինիստիկ եղանակով (03 §1.4)։
- Ինտելեկտուալ ուսուցում (intelligent tutoring) լեզվական մեծ մոդելների (LLM) միջոցով. ռիսկերը՝ հալյուցինացիաներ,
  ոչ դետերմինիստիկություն, հուշման ներարկում (prompt injection), արժեք (03 §6.1)։

**1.3 Տեխնոլոգիաներ** (յուրաքանչյուրի համար՝ ԻՆՉ / ԻՆՉՈՒ / այլընտրանքներ — 03 §2–5)
- Java 21, Spring Boot 4.1 (Web MVC, Security 7, Data JPA / Hibernate 7, Validation), Flyway, springdoc-openapi։
- PostgreSQL 17՝ `jsonb`-ով. Testcontainers՝ H2-ի փոխարեն։
- React 19, TypeScript, Vite, MUI, React Router, Axios։
- Docker, Docker Compose, nginx. LocalStack՝ որպես ընտրովի AWS էմուլյատոր։
- Claude API՝ պաշտոնական Anthropic Java SDK-ի միջոցով. կառուցվածքավորված ելքեր (structured outputs). փորձնական
  (mock) մատակարար (03 §6, 09)։
- Նկարներ՝ 1–4։

**1.4 Արհեստական բանականության (ԱԲ) անվտանգ օգտագործման մեթոդներ** — «ԱԲ-ն խորհուրդ է տալիս, հավելվածը՝
որոշում», դետերմինիստիկ գնահատում, ելքային տվյալների վավերացում, նվազագույն տեղեկատվությամբ հուշումներ (prompts),
պահուստային տարբերակ (fallback) (09 §4)։

## Բաժին 2 — Համակարգի նախագծում և ծրագրային իրականացում

**2.1 Պահանջներ** — դերակատարներ, FR-1…FR-22, NFR-1…NFR-8, MVP հոսքեր (02. Նկ. 6)։

**2.2 Ճարտարապետություն** — մոդուլային մոնոլիտ (ADR-1), փաթեթավորում ըստ ֆունկցիոնալության (package by feature,
ADR-2), DTO-ների տարանջատում (ADR-3), վիճակ չպահող (stateless) JWT (ADR-4), սցենարը՝ որպես տվյալ (ADR-5),
դետերմինիստիկ միավորավորում (ADR-6), սիմուլյացված ռեսուրսներ (ADR-7), ԱԲ մատակարարի աբստրակցիա (ADR-8),
Flyway (ADR-9) (04. Նկ. 2, 5)։

**2.3 Տվյալների բազա** — ձևանմուշային և նմուշային (instance) աղյուսակներ, միավորների պատկերներ (snapshots),
`jsonb`՝ միայն ճկուն ատրիբուտների համար, մասնակի եզակի ինդեքս (partial unique index)՝ մեկ ակտիվ փորձի համար,
enum-ները արտացոլող CHECK սահմանափակումներ (05. Նկ. 7)։

**2.4 Backend-ի իրականացում** — մոդուլների կառուցվածք, REST API, սխալների միասնական ձևաչափ, տրանզակցիաների
նախագծում՝ առանց ԱԲ կանչերի ընթացքում տվյալների բազայի տրանզակցիաներ պահելու (06, 16 Քայլեր 2–7. Նկ. 10)։

**2.5 Սիմուլյացիայի շարժիչ** — կենսացիկլ, գործողությունների կատալոգ, լոգերի աստիճանական բացահայտում (progressive
disclosure), ազդեցությունները ռեսուրսների վրա, վերլուծաբանի իրադարձություններ, միավորավորման կանոններ և բանաձև,
դետերմինիզմ (08. Նկ. 8, 9, 11, 12)։

**2.6 ԱԲ ինտեգրում** — ԱԲ-ի չորս հնարավորություն, մատակարարի աբստրակցիա, հուշման կառուցվածք, վավերացում
(լուծման արտահոսքի ստուգում, JSON-ի վերլուծություն), խիստ ժամանակային սահմանափակում (timeout), պահուստային
տարբերակ, աուդիտի մատյան, սցենարների վավերացված տարբերակներ (09. Նկ. 4, 12, 13)։

**2.7 Անվտանգություն** — նույնականացման հոսք, թույլտվությունների շերտեր, սեփականության ստուգումներ՝ 404
պատասխանով, սպառնալիքների մոդել (10)։

**2.8 Frontend** — կառուցվածք, տիպավորված API շերտ, երթուղիների պաշտպանիչներ (route guards), ակտիվ
սիմուլյացիայի էջը (07, 16 Քայլեր 8–10)։

**2.9 Թեստավորում և տեղակայում** — թեստավորման ռազմավարություն և թեստերի ցանկ (backend-ի 81 թեստ), Docker
կարգավորում (11, 12. Նկ. 3)։

**Իրականացման ընթացքում ծագած խնդիրներ, որոնք արժե քննարկել** (16-ից)՝
- Hibernate-ի կողմից ներդրման (insert) կատարումը ջնջումից (delete) առաջ՝ եզակի բանալիներով դուստր տարրերը
  փոխարինելիս։
- `@Transactional` մեթոդի ինքնականչը (self-invocation), որը շրջանցում է Spring-ի պրոքսին։
- React-ի էֆեկտը, որն արդի Chrome-ում վերադարձնում էր `scrollIntoView`-ի Promise-ը։
- Spring Boot 4 / Jackson 3 փաթեթների փոփոխությունները։

## Բաժին 3 — Մշակված հարթակի ֆունկցիոնալ հնարավորությունները և արդյունքները

**3.1 Ուսանողի գործառույթներ** (13. Նկ. 14–18) — գրանցում/մուտք, վահանակ (dashboard), սցենարների կատալոգ,
ներածական տեղեկանք (briefing), ակտիվ սիմուլյացիա (հետաքննություն, ապացույցների վահանակ, արձագանքման
գործողություններ, ԱԲ օգնական), արդյունք՝ ԱԲ հետադարձ կապով, առաջընթաց և ԱԲ առաջարկություններ։

**3.2 Ադմինիստրատորի գործառույթներ** (14. Նկ. 19–20) — վահանակ, օգտատերերի կառավարում, սցենարների ստեղծում՝
ապացույցներով, սպասվող գործողություններով և միավորավորման կանոններով, սցենարների ԱԲ տարբերակներ, փորձեր՝ ԱԲ
փոխազդեցությունների մատյանով, տարածված սխալների վերլուծություն։

**3.3 Ցուցադրական սցենարներ** — SSH brute force (ցանց), վտանգված նույնականացման տվյալներ (նույնականացում),
հանրային bucket (պահոց). յուրաքանչյուրում՝ 10 սպասվող գործողություն՝ ընդհանուր 100 միավոր արժեքով, շեղող
(distractor) և վնասակար գործողություններ, ժամանակագրության 11–13 իրադարձություն, աստիճանական բացահայտում,
4 հուշում (`backend/src/main/resources/scenarios`)։

**3.4 Արդյունքներ / ստուգում**

| Ասպեկտ | Արդյունք |
|--------|----------|
| Ավտոմատացված թեստեր | Backend-ի 81 թեստ (միավորային, Mockito, MockMvc + Testcontainers) — բոլորը հաջողված |
| Դետերմինիզմ | Սկրիպտավորված անցումը ստացավ ճիշտ ձեռքով հաշվարկված արժեքը (58/100. 10+15+15+20+10−10−2) |
| Անվտանգություն | Ուսանողները ադմինիստրատորի API-ում ստանում են 403. այլ ուսանողների սիմուլյացիաները վերադարձնում են 404. կեղծված JWT → 401 |
| ԱԲ-ի հուսալիություն | Մատակարարի բացառությունը, ժամանակի սպառումը, անվավեր JSON-ը և լուծումը բացահայտող հուշումները բոլորը փոխարինվում են վավեր պահուստային պատասխանով (թեստավորված) |
| Տեղակայում | Ամբողջական համակարգը գործարկվում է `docker compose up --build` հրամանով (ստուգված) |
| Օգտատիրոջ միջերես | Բոլոր հիմնական էջերը ձեռքով ստուգված են Chrome-ում |

**3.5 Սահմանափակումներ և հետագա աշխատանք**
- Claude API-ի իրական կանչերն իրականացված են, սակայն առանց API բանալու գործարկման ընթացքում ստուգված չեն։
- Frontend-ի ավտոմատացված թեստեր չկան. չկան նաև թարմացման թոքեններ (refresh tokens) և մուտքի փորձերի
  հաճախականության սահմանափակում (rate limiting)։
- LocalStack-ի ինտեգրումը միայն նախապատրաստված է (ընտրովի պրոֆիլ), սցենարներում չի օգտագործվում։
- Հնարավոր ընդլայնումներ՝ նոր սցենարներ (IAM արտոնությունների ընդլայնում, տվյալների արտահանում), թիմային
  վարժանքներ, ԱԲ-ի կողմից գեներացված անհատական հուշումների տարբերակներ յուրաքանչյուր ուսանողի համար, Playwright
  E2E թեստեր, նույնականացում HttpOnly cookie-ների միջոցով։

# 15 — Ավարտական աշխատանքի նյութ

Նյութը կազմակերպված է ավարտական աշխատանքի երեք բաժինների համաձայն։ Յուրաքանչյուր կետ հղվում է մանրամասն
փաստաթղթին. նկարները թվարկված են [thesis-figures.md](thesis-figures.md)-ում։ Այս մոդուլի թեզի պատմությունը՝
**AI-ով աջակցվող հեղինակման և որակի ապահովման հարթակ կիբերմիջադեպային ուսումնական բովանդակության համար**։
Սովորողին ուղղված գործարկման միջավայրը (սովորողները խաղարկում են սցենարները, փորձերի գնահատում, առաջընթաց) թիմի
մյուս անդամի մոդուլն է. հրապարակված սցենարների տարբերակները երկու մոդուլների փոխանցման կետն են։

## Բաժին 1 — Հարթակում կիրառված տեխնոլոգիաների և մեթոդների հետազոտություն

**1.1 Խնդրի տիրույթը**
- Ամպային համատեղ պատասխանատվության մոդելը. ամպային միջադեպերի մեծ մասը հաճախորդի կողմի սխալ կարգավորումներ և
  ինքնության վտանգումներ են (03 §1.1)։
- Միջադեպի արձագանքման կյանքի ցիկլը (NIST SP 800-61) որպես կառուցվածք, որը ուսումնական սցենարը պետք է սովորեցնի՝
  հայտնաբերել → հետաքննել → զսպել → վերացնել → վերականգնել → ամրապնդել (03 §1.2, Նկ. 1)։
- Ամպային մատյանների աղբյուրները, որոնք սցենարը պետք է արժանահավատորեն սիմուլյացնի՝ auth մատյաններ, աուդիտի հետք,
  մուտքերի մատյաններ, հոսքերի մատյաններ, պահեստի հասանելիության մատյաններ, սպառնալիքների հայտնաբերման ահազանգեր
  (03 §1.3)։

**1.2 Ուսումնական բովանդակության մեթոդները**
- Կիբերպոլիգոններ ընդդեմ նախապես հեղինակված տելեմետրիայով սիմուլյացիայի ընդդեմ տեսական դասընթացների. նախապես
  հեղինակված տելեմետրիան որոշումների հոսքը սովորեցնում է անվտանգ, էժան և դետերմինիստիկ կերպով — և բովանդակության
  որակը դարձնում է կրիտիկական գործոն (03 §1.4)։
- Սցենարը որպես տվյալ. մեկ դեկլարատիվ փաստաթուղթ (ռեսուրսներ, ժամանակագրություն, գնահատվող գործողություններ)
  սցենարին հատուկ կոդի փոխարեն. նույն գաղափարը, որը շարժիչը դարձրեց ընդհանրական, այժմ հնարավոր է դարձնում
  հեղինակման գործիքակազմը (17 §2)։
- LLM-ով աջակցվող բովանդակության գեներացում. ռիսկերը՝ հալյուցինացիա, կառուցվածքի վնասում, ոչ դետերմինիստիկություն,
  prompt injection, արժեք — և այս նախագծում չափված մեղմացումները (03 §6, 09 §4)։

**1.3 Տեխնոլոգիաները** (յուրաքանչյուրը ԻՆՉ / ԻՆՉՈՒ / այլընտրանքներ ձևաչափով — 03 §2–5)
- Java 21, Spring Boot 4.1 (Web MVC, Security 7, Data JPA / Hibernate 7, Validation), Flyway, springdoc-openapi։
- PostgreSQL 17՝ `jsonb`-ով (տարբերակների պատկերներ, որակի հաշվետվություններ). Testcontainers՝ H2-ի փոխարեն։
- React 19, TypeScript, Vite, MUI, React Router, Axios. react-i18next՝ երկլեզու ինտերֆեյսի համար։
- Docker, Docker Compose, nginx. LocalStack՝ որպես ըստ ցանկության AWS էմուլյատոր։
- Claude API՝ պաշտոնական Anthropic Java SDK-ի միջոցով. mock մատակարար՝ օֆլայն, դետերմինիստիկ աշխատանքի համար
  (03 §6, 09)։
- Նկարներ՝ 1–4։

**1.4 AI-ի անվտանգ կիրառման մեթոդները** — «AI-ն առաջարկում է, հավելվածը որոշում է». կառուցվածքային համարժեքության
ստուգում սևագրի նկատմամբ, նույն վավերացնողը բոլոր մուտքի կետերի համար, կոշտ ժամանակային սահմանափակումներ,
դետերմինիստիկ պահուստ, աուդիտի գրանցում, հուշագրերում սահմանազատված անվստահելի մուտք (09 §4, 17 §4)։

## Բաժին 2 — Համակարգի նախագծում և ծրագրային իրականացում

**2.1 Պահանջներ** — դերակատարներ, հեղինակման հարթակի ֆունկցիոնալ և ոչ ֆունկցիոնալ պահանջներ, MVP հոսքեր (02)։

**2.2 Ճարտարապետություն** — մոդուլային մոնոլիտ (ADR-1), փաթեթավորում ըստ ֆունկցիայի (ADR-2), DTO-ների
տարանջատում (ADR-3), վիճակազուրկ JWT (ADR-4), սցենարը որպես տվյալ (ADR-5), դետերմինիստիկ գնահատման կանոններ
(ADR-6), սիմուլյացված ռեսուրսներ (ADR-7), AI մատակարարի աբստրակցիա (ADR-8), Flyway (ADR-9) (04. Նկ. 2, 5)։

**2.3 Տվյալների բազա** — սցենարի ձևանմուշային աղյուսակներ, անփոփոխելի `scenario_versions` պատկերներ `jsonb`-ում,
կարգավիճակ/վերանայում կյանքի ցիկլ, enum-ները արտացոլող CHECK սահմանափակումներ, `ai_interactions` աուդիտի աղյուսակ
(05. Նկ. 7)։

**2.4 Backend-ի իրականացում** — մոդուլների կառուցվածք, հեղինակման հարթակի REST API, սխալների միասնական ձևաչափ,
տրանզակցիաների նախագծում, որը AI կանչերը պահում է տվյալների բազայի տրանզակցիաներից դուրս (06, 16. Նկ. 10)։

**2.5 Հեղինակման հոսքը — այս մոդուլի տեխնիկական միջուկը** (17. Նկ. 6, 8, 9, 11)
- *Գեներացում*. ստուգված ձևանմուշներ ըստ սցենարի տեսակի, պարամետրերի համաձայնեցված փոխարինում, ըստ ցանկության AI
  հղկում։
- *Կախվածությունների գրաֆ*. գործողությունները, իրադարձությունները և ռեսուրսները՝ որպես հանգույցներ.
  նախապայման / բացահայտում / թիրախ / ազդեցություն կողեր։
- *Վավերացում*. դաշտերի և խաչաձև հղումների կանոններ՝ գումարած գրաֆի մակարդակի վերլուծություն (սխալներ ընդդեմ
  նախազգուշացումների) — օրինակ՝ միայն վնասակար գործողությամբ հասանելի ապացույց, փուլերի շրջում, վտանգավոր ուղու
  բացակայություն։
- *Թեստային գործարկիչ*. հիշողության մեջ խաղարկում է ճիշտ ուղին և վտանգավոր ուղին ճիշտ այն գնահատման կանոններով,
  որոնք կիրառում է ուսանողական մոդուլը (`ScoringEngine`-ը ընդհանուր է). ճիշտ ուղին պետք է հասնի 100 %-ի,
  վտանգավոր ուղին պետք է ձախողվի։
- *Որակի գնահատական*. 0–100՝ վավերականություն (25), թեստեր (25), ծածկույթ (20), մանկավարժություն (20),
  կառուցվածք (10), յուրաքանչյուրը տեքստային հիմնավորումով. գնահատականներ՝ EXCELLENT / GOOD / FAIR / POOR։
- *Հրապարակման շեմեր*. սերվերի կողմից կրկնակի ստուգումներ (առանց սխալների, երկու ուղիներն անցնում են, գնահատականը
  ≥ 70), որից հետո գրվում է անփոփոխելի տարբերակ. հրապարակված սցենարի խմբագրումը վերաբացում է սևագիրը՝ չդիպչելով
  հրապարակված տարբերակին. վերականգնում։

**2.6 AI ինտեգրում** — երեք AI խնդիր (գեներացման հղկում, վարիացիա, ըստ պահանջի թարգմանություն), մատակարարի
աբստրակցիա, հուշագրի կառուցվածք, կառուցվածքային վավերացում, կոշտ ժամանակային սահմանափակում, պահուստ,
`ai_interactions` աուդիտ (09. Նկ. 4, 12, 13)։

**2.7 Անվտանգություն** — նույնականացման հոսք, միայն ADMIN լիազորում `/api/admin/**`-ի վրա, սերվերի կողմից
պարտադրվող հրապարակման շեմեր, սպառնալիքների մոդել՝ ներառյալ prompt injection ադմինիստրատորի նկարագրության միջոցով
(10, 17 §4)։

**2.8 Frontend** — ադմինի SPA-ի կառուցվածքը, տիպավորված API շերտ, երթուղիների պահակներ, սցենարի խմբագրիչը՝
վերանայման/գրաֆի/տարբերակների վահանակներով. երկլեզու ինտերֆեյս տիպավորված ռեսուրսների փաթեթներով (ADR-11) և
բովանդակության ըստ պահանջի AI թարգմանություն (ADR-12) (07, 16. Նկ. 14–20)։

**2.9 Թեստավորում և տեղակայում** — թեստավորման ռազմավարությունը և ցանկը (backend-ի 63 թեստ՝ միավորային,
MockMvc + Testcontainers ինտեգրացիոն), Docker կարգավորումը (11, 12. Նկ. 3)։

**Քննարկման արժանի իրականացման խնդիրներ** (16-ից).
- Hibernate-ի insert-before-delete հերթականությունը եզակի բանալիներով երեխաներին փոխարինելիս։
- `@Transactional`-ի ինքնականչը, որը շրջանցում է Spring proxy-ն։
- React-ի էֆեկտը, որը ընթացիկ Chrome-ում `scrollIntoView`-ից Promise է վերադարձնում։
- Spring Boot 4 / Jackson 3 փաթեթների փոփոխությունները։
- Flyway միգրացիայի վերագրումը ծավալի փոփոխության ժամանակ. գոյություն ունեցող տվյալների բազաները պետք է
  վերստեղծվեն, իսկ ջնջված միգրացիայի հնացած կոմպիլացված պատճենը `target/classes`-ում տալիս է «Found more than one
  migration with version X» մինչև մաքուր build։
- Ծավալի փոփոխությունն ինքնին՝ որպես ինժեներական վարժություն. ուսանողական գործարկման միջավայրի ջնջում՝ պահելով
  գնահատման կանոնները և սցենարի մոդելը, որոնք ընդհանուր են մյուս մոդուլի հետ (16, 17 §1)։

## Բաժին 3 — Մշակված հարթակի ֆունկցիոնալ հնարավորությունները և արդյունքները

**3.1 Ադմինիստրատորի ֆունկցիաները** (14, 17. Նկ. 14–20) — մուտք. վահանակ՝ հեղինակման հոսքով և բովանդակության
կարգավիճակով. սցենարների գեներատոր (տեսակ, բարդություն, ակտիվ, հարձակվողի IP, տարածաշրջան, ազատ նկարագրություն,
ըստ ցանկության AI). կառուցվածքային խմբագրիչ ռեսուրսների, ժամանակագրության, գործողությունների, գնահատման և
հուշումների համար. կախվածությունների գրաֆ. վավերացման արդյունքներ. թեստային գործարկումներ. որակի գնահատական՝
բաշխումով. հրապարակում՝ պարտադրված շեմերով. տարբերակների պատմություն՝ վերականգնումով. երկլեզու ինտերֆեյս՝ ըստ
պահանջի թարգմանությամբ։

**3.2 Ցուցադրական սցենարները** — SSH կոպիտ ուժ (ցանց), վտանգված հավատարմագրեր (նույնականացում), հանրային bucket
(պահեստ). յուրաքանչյուրը մատակարարվում է որպես գեներատորի ձևանմուշ և որպես գործարկման ժամանակ 1-ին տարբերակով
հրապարակված սկզբնական սցենար. յուրաքանչյուրն ունի ամբողջական ժամանակագրություն՝ աստիճանական բացահայտումով,
ապացույցների նշաններ, շեղող և վնասակար գործողություններ, հուշումներ և սպասվող գործողությունների 100 միավոր
(`backend/src/main/resources/scenarios`)։

**3.3 Արդյունքներ / ստուգում**

| Կողմ | Արդյունք |
|--------|--------|
| Ավտոմատացված թեստեր | Backend-ի 63 թեստ (միավորային, Mockito, MockMvc + Testcontainers) — բոլորը հաջողված |
| Բովանդակության որակի շեմեր | Բոլոր երեք սկզբնական սցենարները վավեր են, անցնում են երկու թեստային ուղիները և հասնում հրապարակման շեմին (հաստատված թեստերով) |
| Հրապարակման պարտադրում | Վավերացման սխալներով կամ ցածր որակի գնահատականով սևագիրը սերվերի կողմից մերժվում է `422 PUBLISH_BLOCKED`-ով (թեստավորված) |
| Տարբերակավորում | Հրապարակված տարբերակներն անփոփոխելի են. խմբագրումը վերաբացում է սևագիրը. վերականգնումը ստուգված է (թեստավորված) |
| Անվտանգություն | Անանուն և ոչ ադմինիստրատոր հարցումները `/api/admin/**`-ին մերժվում են. կեղծված JWT → 401 (թեստավորված) |
| AI-ի հուսալիություն | Մատակարարի բացառությունը, ժամանակի գերազանցումը, անվավեր JSON-ը և կառուցվածքը խախտող ելքը բոլորն անցնում են դետերմինիստիկ սևագրին (թեստավորված) |
| Տեղակայում | Ամբողջ համակարգը գործարկվում է `docker compose up --build`-ով (սխեմայի վերագրումից հետո անհրաժեշտ է թարմ ծավալ) |

**3.4 Սահմանափակումներ և ապագա աշխատանք**
- Claude API-ի իրական կանչերը իրականացված են, բայց առանց API բանալու գործարկման մեջ չստուգված (mock մատակարարը
  ստուգված է)։
- Ավտոմատացված frontend թեստեր չկան. refresh տոկեններ կամ մուտքի արագության սահմանափակում չկա։
- Ադմինիստրատորի հաշիվները ստեղծվում են օպերատորի կողմից (միջավայրային փոփոխականներ). հավելվածում օգտատերերի
  կառավարում չկա։
- Ուսանողական մոդուլը հրապարակված տարբերակները սպառում է անմիջապես տվյալների բազայից. մոդուլների միջև միայն
  ընթերցման HTTP պայմանագիրը ապագա աշխատանք է։
- Հնարավոր ընդլայնումներ՝ ավելի շատ սցենարի տեսակներ (IAM արտոնությունների բարձրացում, տվյալների արտահոսք),
  վավերացման AI բացատրություններ, տարբերակների միջև սցենարի տարբերություն (diff), Playwright E2E թեստեր, HttpOnly
  cookie նույնականացում։

# 01 — Նախագծի ընդհանուր նկարագիր

**Նախագծի վերնագիր.** Արհեստական բանականության կիրառմամբ ամպային կիբեռմիջադեպերի մոդելավորման և անվտանգության մասնագետների ուսուցման հարթակի մշակում

**Աշխատանքային անվանում.** CyberSim

## 1. Խնդիրը

Ամպային անվտանգության միջադեպերը (գողացված հավատարմագրեր (credentials), ամբողջական ընտրանքի (brute-force) գրոհներ,
հրապարակայնորեն հասանելի պահոցներ, IAM-ի ավելորդ իրավունքներ) իրական արտահոսքերի ամենատարածված պատճառներից են։
Անվտանգության մասնագետներին նման միջադեպերին *արձագանքելու* ուսուցանելը բարդ է.

- Իրական ամպային միջավայրերն ուսուցման համար թանկ են և ռիսկային. սխալը կարող է առաջացնել
  իրական վնաս կամ իրական ծախս։
- Տեսական դասընթացները սովորեցնում են հասկացություններ, սակայն հազվադեպ են ուսանողներին հնարավորություն տալիս
  գործնականում կիրառել հետաքննության և արձագանքման *աշխատահոսքը* (կարդալ մատյանները → գտնել ապացույցները → նույնականացնել վտանգված ռեսուրսը → մեկուսացնել → վերականգնել)։
- Հետադարձ կապը սովորաբար ուշացած է և ընդհանրական. դասախոսը չի կարող մանրամասն վերանայել ուսանողի յուրաքանչյուր փորձ։

## 2. Լուծումը

CyberSim-ը վեբ հարթակ է, որտեղ ուսանողները հետաքննում են **մոդելավորված** ամպային կիբեռմիջադեպեր
անվտանգ, մեկուսացված, դետերմինիստիկ միջավայրում.

1. Ուսանողն ընտրում է սցենար (օրինակ՝ *SSH brute-force գրոհ ամպային վիրտուալ մեքենայի դեմ*)։
2. Հարթակը ստեղծում է մոդելավորման անձնական նմուշ՝ վիրտուալ ամպային ռեսուրսներ, մատյաններ, ահազանգեր և
   միջադեպի ժամանակագրություն։
3. Ուսանողը հետաքննում է՝ ուսումնասիրում է մատյանների աղբյուրները, որոնք բացահայտում են նոր ապացույցներ, և կատարում է
   արձագանքման գործողություններ (մեկուսացնել վիրտուալ մեքենան, անջատել հավատարմագրերը, փոխարինել բանալիները, …)։
4. **AI օգնականը**, որը տիրապետում է սցենարի համատեքստին, տալիս է հուշումներ՝ առանց ամբողջական
   լուծումը բացահայտելու, և պատասխանում է հարցերին։
5. Երբ ուսանողն ավարտում է, դետերմինիստիկ **գնահատման շարժիչը** համեմատում է նրա գործողությունները
   սցենարի ակնկալվող գործողությունների հետ, իսկ **AI-ը** ձևավորում է անհատականացված հետադարձ կապ
   (ուժեղ կողմեր, սխալներ, բաց թողնված ապացույցներ, գործողությունների հերթականություն)։
6. Առաջընթացը պահպանվում է. AI-ը առաջարկում է հետագայում ուսումնասիրելու թեմաներ։
7. Ադմինիստրատորները ստեղծում և խմբագրում են սցենարներ, կարգավորում ակնկալվող գործողություններն ու գնահատումը, և դիտում
   փորձերը, վիճակագրությունը և ամենատարածված սխալները։

Հարթակում ոչինչ չի առնչվում իրական արտաքին համակարգերին։ Բոլոր «ամպային ռեսուրսները» հարթակի սեփական
տվյալների բազայի տողեր են. բոլոր «գրոհները» նախապես կազմված մատյանային գրառումներ են։

| G5 | Ադմինիստրատորի վահանակ՝ սցենարների ստեղծման և վերլուծության համար։ |
| G6 | Ավտոմատացված թեստեր կրիտիկական տրամաբանության համար (անվտանգություն, վիճակների մեքենա, գնահատում, AI-ի պահուստային լուծում)։ |
| G7 | Թեզի համար պատրաստ փաստաթղթավորում, որը յուրաքանչյուր կարևոր որոշման համար բացատրում է ԻՆՉ, ԻՆՉՈՒ և ԻՆՉՊԵՍ։ |

## 4. Առաջին տարբերակի շրջանակը (MVP)

Երեք ամբողջությամբ իրականացված սցենար (ընտրված են, քանի որ դրանք ամենապարզն են հասկանալու և բացատրելու համար).

1. **SSH Brute-Force ամպային վիրտուալ մեքենայի վրա** — սկսնակ մակարդակ։
2. **Կասկածելի մուտք վտանգված հավատարմագրերով** — սկսնակ մակարդակ։
3. **Հրապարակայնորեն հասանելի պահոցի բաքեթ (storage bucket)** — սկսնակ/միջին մակարդակ։

MVP-ի շրջանակից դուրս են (փաստաթղթավորված են որպես հետագա աշխատանք)՝ բազմախաղացող/թիմային վարժություններ, իրական ամպային
մատակարարի ինտեգրում, իրական գրոհային երթևեկություն, վկայականներ/գնահատականների արտահանում։

## 5. Ռեպոզիտորիայի կառուցվածքը

```
cyber-sim/
├── backend/            Spring Boot 4 (Java 21) modular monolith
├── frontend/           React + TypeScript + Vite single-page application
├── docs/
│   ├── en/             English documentation (primary)
│   └── hy/             Armenian translation of the same documents
├── docker-compose.yml  PostgreSQL, backend, frontend, optional LocalStack
├── .env.example        All configurable environment variables (no secrets)
└── README.md
```

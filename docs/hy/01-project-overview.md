# 01 — Նախագծի ակնարկ

**Նախագծի վերնագիրը՝** Արհեստական բանականության կիրառմամբ ամպային կիբերմիջադեպերի սիմուլյացիայի և անվտանգության մասնագետների պատրաստման հարթակի մշակում

**Աշխատանքային անվանումը՝** CyberSim

**Ծավալի պատմությունը։** Հարթակը մշակում է երկու հոգուց բաղկացած թիմ։ Այս պահոցի առաջին տարբերակը պարունակում էր
ամբողջ արտադրանքը, ներառյալ ուսանողական կողմը (ուսանողները կատարում էին սիմուլյացված միջադեպեր, AI ուսուցիչ,
առաջընթաց և վերլուծություն)։ Այնուհետև ուսանողին ուղղված գործարկման միջավայրը տեղափոխվեց թիմի մյուս անդամի մոդուլ,
իսկ այս պահոցը կենտրոնացավ **ադմինիստրատորի սցենարների հեղինակման հարթակի** վրա՝ միջադեպային սցենարների գեներացում,
խմբագրում, վավերացում, թեստային գործարկում, որակի գնահատում, հրապարակում և տարբերակավորում։ Հրապարակված սցենարների
տարբերակները երկու մոդուլների միջև փոխանցման կետն են։ Փոփոխությունը գրանցված է
[16 — Իրականացման մատյանում](16-implementation-log.md), իսկ նոր հարթակը նկարագրված է
[17 — Ադմինիստրատորի սցենարների հեղինակման հարթակ](17-admin-authoring-platform.md) փաստաթղթում. 02–14 փաստաթղթերը
նկարագրում են ընթացիկ, միայն ադմինիստրատորին ուղղված ծավալը։

## 1. Խնդիրը

Միջադեպերի արձագանքման ուսուցումը կանգնած է բովանդակության որակի վրա։ Ուսումնական սցենարը զուտ տեքստ չէ — այն
սիմուլյացված ամպային ռեսուրսների, մատյանների և ահազանգերի հարձակման ժամանակագրության, ապացույցների, գնահատվող
արձագանքման գործողությունների կատալոգի և դրանց կախվածությունների համահունչ համակարգ է։ Նման բովանդակությունը որակով
հեղինակելը դժվար է.

- **Ձեռքով գրված սցենարները խափանվում են անաղմուկ։** Կախված հղումը (գործողություն, որը թիրախավորում է գոյություն
  չունեցող ռեսուրս), շրջանաձև նախապայմանը, ապացույցը, որին կարելի է հասնել միայն *սխալ* գործողությամբ, կամ
  անհավասարակշիռ միավորները — սրանցից ոչ մեկը տեսանելի չէ JSON-ը կարդալով, բայց յուրաքանչյուրը փչացնում է
  վարժությունը սովորողի համար։
- **Որակը սուբյեկտիվ է առանց չափման։** Դասախոսները օբյեկտիվ միջոց չունեն պարզելու, թե սցենարը որևէ բան սովորեցնո՞ւմ
  է՝ կա՞ն շեղող գործողություններ, հուշումներ, վտանգավոր ուղի, ապացույցների աստիճանական բացահայտում։
- **AI-ը կարող է արագ սևագրել բովանդակություն, բայց AI-ի ելքին կուրորեն վստահել չի կարելի։** Գեներացված սցենարները
  պետք է ենթարկվեն նույն կառուցվածքային կանոններին, ինչ ձեռքով գրվածները, նախքան սովորողը դրանք կտեսնի։
- **Բովանդակությունը զարգանում է։** Սցենարները վերանայումների կարիք ունեն, մինչդեռ սովորողները պետք է շարունակեն
  տեսնել կայուն, հաստատված տարբերակը։

## 2. Լուծումը

CyberSim-ը (այս մոդուլը) ադմինիստրատորի հեղինակման հարթակն է։ Դասախոսը սցենարը առաջին սևագրից հասցնում է
հրապարակված, անփոփոխելի տարբերակի ութ քայլից բաղկացած հոսքով.

1. **Գեներացում**՝ ստուգված ձևանմուշից (SSH կոպիտ ուժ, վտանգված հավատարմագրեր, հանրային պահեստ)՝ ցանկության դեպքում
   պատմողական տեքստի AI հղկումով (*AI-ն առաջարկում է, հավելվածը որոշում է*)։
2. **Խմբագրում**՝ սցենարի յուրաքանչյուր մաս — ռեսուրսներ, ժամանակագրություն, գործողություններ, գնահատում,
   հուշումներ — կառուցվածքային խմբագրիչում։
3. **Գրաֆ**՝ հարթակը կառուցում է կախվածությունների գրաֆը (գործողություններ, իրադարձություններ, ռեսուրսներ,
   բացահայտումներ, նախապայմաններ), որպեսզի կառուցվածքը տեսանելի լինի, ոչ թե ենթադրվի։
4. **Վավերացում**՝ դաշտերի և խաչաձև հղումների կանոններ՝ գումարած գրաֆի մակարդակի վերլուծություն (օրինակ՝ ապացույց,
   որը հասանելի է միայն վնասակար գործողությամբ), որոնք տալիս են սխալներ և նախազգուշացումներ։
5. **Թեստային գործարկում**՝ սցենարը խաղարկվում է հիշողության մեջ — ճիշտ ուղին պետք է հավաքի 100 %, վտանգավոր ուղին
   պետք է ձախողվի — ճիշտ նույն գնահատման կանոններով, որոնք կիրառում է ուսանողական մոդուլը։
6. **Որակի գնահատական**՝ 0–100 միավոր վավերականության, թեստերի, ծածկույթի, մանկավարժության և կառուցվածքի վրա՝
   յուրաքանչյուրը հիմնավորումով։
7. **Հրապարակում**՝ թույլատրվում է միայն, երբ վավերացումը մաքուր է, երկու թեստային ուղիներն անցնում են, և որակի
   գնահատականը հասնում է շեմին (70)։ Հրապարակումը սցենարը պահում է որպես անփոփոխելի տարբերակ։
8. **Տարբերակներ**՝ յուրաքանչյուր հրապարակված տարբերակ պահպանվում է, համեմատելի է և վերականգնելի է նոր սևագրի մեջ։

Սցենարի բովանդակությունն ինքնին նկարագրում է **սիմուլյացված** միջադեպեր. բոլոր «ամպային ռեսուրսները» հարթակի
տվյալների բազայի տողեր են, բոլոր «հարձակումները»՝ նախապես հեղինակված մատյանի գրառումներ։ Ոչինչ չի շոշափում իրական
արտաքին համակարգեր, և ոչ մի հրաման երբեք չի կատարվում։

| # | Նպատակ |
|---|------|
| G1 | Գործարկվող, ցուցադրելի ամբողջական հավելված (Spring Boot + PostgreSQL + React)։ |
| G2 | Սցենարը որպես տվյալ. մեկ վավերացված JSON փաստաթուղթ է վարում գեներացումը, խմբագրումը, թեստավորումը և հրապարակումը — առանց սցենարին հատուկ կոդի։ |
| G3 | Իմաստալից AI ինտեգրում — սևագրի գեներացում, սցենարային վարիացիաներ, ինտերֆեյսի ըստ պահանջի թարգմանություն — mock մատակարարով, որպեսզի ամեն ինչ աշխատի առանց վճարովի API բանալու։ |
| G4 | AI-ի ելքը դիտարկել որպես անվստահելի. կառուցվածքային համարժեքության ստուգումներ, վավերացում, ժամանակի սահմանափակումներ, պահուստային մեխանիզմներ, աուդիտի գրանցում։ |
| G5 | Օբյեկտիվ, բացատրելի որակի չափում և սերվերի կողմից պարտադրվող հրապարակման շեմեր։ |
| G6 | Ավտոմատացված թեստեր կրիտիկական տրամաբանության համար (վավերացում, գրաֆի վերլուծություն, թեստային գործարկիչ, որակի գնահատական, հրապարակման շեմեր, անվտանգություն, AI-ի պահուստային մեխանիզմ)։ |
| G7 | Ավարտական աշխատանքին պատրաստ փաստաթղթավորում, որը բացատրում է ԻՆՉԸ, ԻՆՉՈՒՆ և ԻՆՉՊԵՍԸ յուրաքանչյուր կարևոր որոշման համար՝ անգլերեն և հայերեն։ |

## 4. Առաջին տարբերակի (MVP) ծավալը

Երեք ամբողջությամբ իրականացված սցենարի տեսակ, որոնցից յուրաքանչյուրը մատակարարվում է որպես ստուգված ձևանմուշ և
որպես հրապարակված սկզբնական սցենար.

1. **SSH կոպիտ ուժի հարձակում ամպային վիրտուալ մեքենայի վրա** — ցանց։
2. **Կասկածելի մուտք վտանգված հավատարմագրերով** — նույնականացում։
3. **Հանրայնորեն բաց պահեստային bucket** — պահեստ։

Այս մոդուլի ծավալից դուրս (պատկանում է թիմի մյուս անդամի ուսանողական մոդուլին)՝ սովորողների հաշիվներ,
սիմուլյացիաների կատարում, փորձերի գնահատում, առաջընթացի հաշվառում, սովորողների վերլուծություն։ Ամբողջ MVP-ի
ծավալից դուրս՝ իրական ամպային մատակարարի ինտեգրում, կենդանի հարձակման թրաֆիկ, թիմային վարժություններ։

## 5. Պահոցի կառուցվածքը

```
cyber-sim/
├── backend/            Spring Boot 4 (Java 21) մոդուլային մոնոլիտ
├── frontend/           React + TypeScript + Vite միաէջ հավելված (ադմինի ինտերֆեյս, EN/HY)
├── docs/
```

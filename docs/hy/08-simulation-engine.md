# 08 — Սցենարի կատարման մոդելը և թեստային գործարկիչը

> Այս փաստաթուղթը սկզբում նկարագրում էր ուսանողին ուղղված սիմուլյացիայի շարժիչը։ Այդ միջավայրը տեղափոխվել է
> թիմի մյուս անդամի մոդուլ (տե՛ս [17-admin-authoring-platform.md](17-admin-authoring-platform.md)). ֆայլն այժմ
> փաստաթղթավորում է այն, ինչ փոխարինել է դրան այստեղ՝ սցենարի սահմանած **կատարման մոդելը** և **թեստային
> գործարկիչը**, որը մինչ հրապարակումը յուրաքանչյուր սցենար հիշողության մեջ խաղում է հենց այդ կանոններով։ Ֆայլի
> անունը պահպանված է, որպեսզի եղած հղումները մնան վավեր։

## 1. Պատասխանատվություններ

Սցենարը պարզապես բովանդակություն չէ — այն սահմանում է կատարվող մոդել. որ գործողություններն են հասանելի, որ
հերթականությամբ են դրանք իմաստ ունենում, որ մատյանի գրառումներն են բացահայտում, և ինչպես է արձագանքում
սիմուլյացված ենթակառուցվածքը։ Հեղինակման հարթակը պետք է երաշխավորի, որ այդ մոդելը իրոք *աշխատում է*, նախքան
տարբերակը կհանձնվի ուսանողի մոդուլին։ Դա `ScenarioTestRunner`-ի գործն է (`am.cybersim.authoring` փաթեթ).
խաղալ սցենարը հիշողության մեջ՝ ուսանողին սպասող նույն կանոններով, և ձախողել հրապարակումը, եթե ինչ-որ բան այն
չէ։ Այն դետերմինիստիկ է և կողմնակի ազդեցություններից զերծ (ո՛չ բազա, ո՛չ օգտատեր), ուստի կարող է աշխատել ամեն
պահպանման ժամանակ և որպես հրապարակման դարպաս։

## 2. Կատարման մոդելը

Կանոնները, որոնք պարտադրում է թեստային գործարկիչը, `ScenarioDefinition` փաստաթղթի իմաստաբանությունն են.

| Կանոն | Տվյալը, որը ղեկավարում է այն |
|------|---------------------|
| Գործողությունը կարելի է կատարել մեկ անգամ. կրկնությունը ազդեցություն չունի | `action_key`-ի եզակիություն |
| Նախապայմանից առաջ կատարված գործողությունը հաշվվում է **սխալ հերթականությամբ** | `prerequisite_action_key` |
| `revealed_by_action_key = NULL` իրադարձությունները տեսանելի են սկզբից | `scenario_events` |
| Հետաքննական գործողության կատարումը **բացահայտում է** նրան հղվող իրադարձությունները (աստիճանական բացահայտում) | `revealed_by_action_key` |
| Արձագանքման գործողությունը կարող է փոխել ռեսուրսի կարգավիճակը (օր.՝ `RUNNING → ISOLATED`) | `target_resource_key` + `effect_status` |
| Յուրաքանչյուր կատարված գործողություն գնահատվում է կատարման պահին | `outcome`, `points`, տուգանքներ (տե՛ս §5) |

Հիշողության մեջ խաղը (`ScenarioTestRunner.play`) սկսում է ռեսուրսների սկզբնական վիճակներից, անցնում
գործողությունների ցանկով, հետևում բացահայտված իրադարձություններին և ռեսուրսների կարգավիճակի
փոփոխություններին, իսկ վերջում գնահատում է խաղարկումը դետերմինիստիկ `ScoringEngine`-ով — նույն բաղադրիչը, որի
կանոնները կիրառում է ուսանողի մոդուլը, ուստի «այստեղ անցնում է» նշանակում է «այնտեղ կանխատեսելի է վարվում»։

## 3. Ճիշտ ուղի

Գործարկիչը հաշվարկում է բոլոր `EXPECTED` գործողությունների՝ կախվածությունները հարգող հերթականությունը
(`ScenarioGraph.topologicalOrder`) և խաղում այն։ Ստուգումներ (բոլորը պետք է անցնեն).

| Ստուգում | Ինչու է կարևոր |
|-------|----------------|
| Բոլոր ճիշտ գործողությունները կատարելի են | նախապայմանների ցիկլը սցենարը կդարձներ անլուծելի |
| Կատարված է վավեր հերթականությամբ, առանց տուգանքների | հայտարարված նախապայմանները իրենք պետք է հերթականությամբ բավարարելի լինեն |
| Հասանելի է առավելագույն միավորը (100 %) | հայտարարված առավելագույնը պետք է իրոք ձեռք բերվի |
| Բոլոր ապացույցները բացահայտելի են | յուրաքանչյուր `evidence = true` իրադարձություն պետք է հասանելի լինի ճիշտ ուղու վրա |
| Միջադեպն ավարտվում է փոփոխված վիճակում | արձագանքը պետք է տեսանելի ազդեցություն ունենա գոնե մեկ ռեսուրսի վրա |
| Ոչ մի ճիշտ գործողություն բաց չի թողնված | կատալոգի ներքին համաձայնություն |

## 4. Վտանգավոր ուղի

Այնուհետև գործարկիչը խաղում է բոլոր `HARMFUL` գործողությունները։ Ստուգումներ.

| Ստուգում | Ինչու է կարևոր |
|-------|----------------|
| Վտանգավոր գործողություններ կան | առանց դրանց «սխալ ճանապարհը» հնարավոր չէ ցուցադրել կամ թեստավորել |
| Յուրաքանչյուր վնասակար գործողություն տուգանվում է | բացասական միավորները պետք է իրոք կարգավորված լինեն |
| Միավորը մնում է ձախողված (&lt; 50 % և raw ≤ 0) | միայն սխալ բաներ անելը չպետք է հաջողություն երևա |
| Միջադեպը չի լուծվում | դրանից հետո յուրաքանչյուր սպասվող գործողություն դեռ պետք է բացակայի |
| Վնասակար գործողությունը նման չէ լուծմանը | վնասակար գործողությունը չպետք է ստանա նույն ռեսուրսի վերջնավիճակը, ինչ ճիշտ արձագանքը |
| Յուրաքանչյուր վնասակար գործողություն բացատրում է, թե ինչու է սխալ | բացատրությունը (≥ 20 նիշ) սխալների ուսուցողական բովանդակությունն է |

## 5. Գնահատում

Գնահատումը դետերմինիստիկ `ScoringEngine`-ն է (ADR-6 — AI-ն երբեք չի մասնակցում գնահատմանը)։ Կանոնները,
կարգավորելի ըստ սցենարի (`out_of_order_penalty`, `hint_penalty`) և ըստ գործողության (`points`).

| Իրավիճակ | Միավորներ |
|-----------|--------|
| `EXPECTED` գործողություն, առաջին անգամ, հերթականությամբ | `+points` |
| `EXPECTED` գործողություն՝ նախապայմանից առաջ | `+points − out_of_order_penalty` (նվազագույնը 0) |
| `NEUTRAL` գործողություն | 0 (զեկուցվում է որպես ավելորդ) |
| `HARMFUL` գործողություն | բացասական `points` |
| Կրկնված գործողություն | 0 |
| Յուրաքանչյուր AI հուշում (ուսանողի կողմում) | `−hint_penalty` |

`rawScore`-ը գումարն է (կարող է բացասական լինել). `maxScore`-ը բոլոր `EXPECTED` միավորների գումարն է.
`scorePercent`-ը սահմանափակված տոկոսն է։ Արդյունքը (`ScoreResult`) պարունակում է մեկ տող յուրաքանչյուր
գնահատված տարրի համար, գումարած բոլոր բաց թողնված սպասվող գործողությունները՝ իրենց բացատրություններով։
Թեստային գործարկիչը օգտագործում է `hintsUsed = 0`. հուշման տուգանքը գոյություն ունի ուսանողի մոդուլի համար,
որը կիրառում է նույն շարժիչը։

## 6. Դետերմինիզմ և վերաօգտագործում

- Ամբողջ փուլաշարը — գրաֆ, վավերացում, թեստային գործարկում, գնահատում, որակի միավոր —
  `ScenarioDefinition`-ի մաքուր ֆունկցիա է։ Նույն մուտք, նույն վճիռ. ո՛չ ժամացույց, ո՛չ պատահականություն,
  ո՛չ I/O։
- Քանի որ թեստային գործարկիչը և ուսանողի մոդուլը կիսում են `ScoringEngine`-ի կանոնները և նույն սահմանման
  փաստաթուղթը (սառեցված `scenario_versions`-ում), հրապարակված սցենարի հայտարարված հատկությունները — լուծելի է,
  առավելագույն միավորը հասանելի է, վտանգավոր ուղին տուգանվում է — գործում են ամենուր, որտեղ տարբերակը
  կատարվում է։
- AI-ով գեներացված բովանդակությունը (գեներացիայի հղկում, վարիացիաներ) կրճատ ճանապարհ չի ստանում. այն
  վերլուծվում, կառուցվածքով ստուգվում, ապա վավերացվում և թեստային գործարկվում է ճիշտ այնպես, ինչպես ձեռքով
  գրված բովանդակությունը («AI-ն առաջարկում է, հավելվածը որոշում է»)։
